# 把已有剧本合集转换为瞬息格式

把下面的转换指令和原来的 JSON 文件一起发给 AI，下载它给出的 UTF-8 JSON 文件，然后打开瞬息「剧本 → 导入剧本」，核对数量并确认导入。请保留原文件以便核对。

## 可直接复制给 AI 的指令

请将我附上的全部剧本转换为「瞬息 · 番外小剧场」的标准剧本 JSON。只转换格式，不续写、不润色、不总结剧本指令。

输出一个 JSON 数组，每条剧本只包含以下四个字段：

```json
[
  {
    "title": "剧本名称",
    "tag": ["标签一", "标签二"],
    "types": "any",
    "content": "完整的原始剧本指令"
  }
]
```

转换规则：

1. `title`：名称字符串，1～120 字符。沿用原标题；确实没有标题时，填写「未命名剧本 1」等顺序名称。
2. `tag`：标签字符串数组。无标签时用 `[]`。每个标签 1～60 字符，最多 100 个。同一条剧本的重复标签只保留一个。原有 category 若是分类名称，可作为标签保存。
3. `types`：一个字符串，只能是 `any`（不限）、`prose`（正文）、`phone`（小手机）、`html`（HTML）。仅当原指令明确指定生成方式时填写对应值；无法判断时写 `any`，不要猜测。它不是数组。
4. `content`：完整原始指令字符串，非空，最多 100 万字符。保留原有换行、人物名、占位符、代码、符号和语言，不替换 `{{char}}`、`{{user}}`。使用合法 JSON 转义保留引号、反斜杠和换行；解析 JSON 后的内容必须与原指令相同。
5. 一条原剧本对应一个数组元素，不把多条合并成一个长文本，也不按一条指令内部的段落拆成多条。必须转换整个合集，不能仅给示例或用省略号代替内容。
6. 只处理瞬息需要的名称、标签、生成方式与指令内容。其他无关元数据不输出。`desc` 如果只是简介，不拼进指令；如果它本身就是完整指令，则用作 `content`。若无法判断哪部分是实际指令，先指出具体条目向我确认，不能把指令丢掉。
7. 不输出原插件 ID、分类 ID、作者、时间或内部配置等字段。不要把本次转换要求放进 `content`。
8. 输出合法的 UTF-8 `.json` 文件。数组外不要套对象，不要写注释或尾逗号，不要添加 Markdown 代码围栏。
9. 交付前验证 JSON 可以解析、每条四个字段齐全，核对原剧本条数与转换后条数一致。在文件之外报告转换条数及任何需要人工核对的条目。如果输出长度不足，按原顺序分成多个合法 JSON 数组文件，明确每个文件的条数和覆盖范围，不截断内容。

## 瞬息导入约定

- 支持一个标准对象或标准对象数组，合集推荐数组；字段名固定为 `title`、`tag`、`types`、`content`。
- 单文件小于 50 MB，1～10000 条；导入后库内最多 10000 条。
- 任一条结构无效会指出条目序号，整批不写入；修正后重新选择文件。
- 名称、指令、方式和标签均相同的条目跳过；标签顺序不同也算重复。同名但内容不同会独立保存，不覆盖已有剧本。
- 导入不自动生成。已导入剧本纳入设置里的「备份全部资料」；本版没有独立剧本导出。
